# 首页部署说明

## 已有发布基线

- 域名：`https://cobuild.110-lab.cn/`
- 归档基线：`20261015-v1`
- 既有服务器发布目录：`/opt/cobuild-homepage/releases/20261015-v1`
- Caddy 提供静态资源，使用独立的 `cobuild-homepage` 目录及 `current` 发布指针。
- 源码导入 GitHub 不触发重新发布，不新增常驻进程或容器。

`production-baseline.json` 来自该次发布的产物清单。它是历史基线，不能代替后续上线时对公网状态的实时核查。

## 后续发布步骤

1. 记录待发布的 Git 提交，运行 `npm ci`、`npm run build`、`npm run test:sites`。
2. 检查桌面和手机布局、应用跳转及素材加载；本首页不实现登录和权限，跳转后的认证由各应用处理。
3. 对 `dist/client/` 生成新的 SHA256 清单，上传至新的独立发布目录。不要覆盖正在使用的目录。
4. 记录当前发布指针及当前网关配置，确认有可用的回滚版本。
5. 核对线上目录与产物清单一致，再切换 `current` 指针。如需调整 Caddy，先校验配置再 reload。
6. 通过公网检查首页、全部静态资源、移动端及应用链接；缺失资源应返回 404。
7. 记录提交、发布目录、产物清单、验收结果与上一版本。

具体服务器访问方式和凭据应由运维私下配置，不提交本仓库。

## 回滚

仅回退本首页的发布指针至前一已验收版本，并检查公网资源。网关由多个服务共用，如必须修改配置，应读取当前配置，只改首页对应区块，保持配置文件 inode，校验后 reload；不得用历史整份配置覆盖当前配置，也不得重启考核、批改等业务服务。

确认回滚成功后保留失败版本及发布记录，便于定位。不要在本次源码归档中执行任何线上切换。
